ADR-0002: Use FastAPI as the backend web framework

Status: Accepted

Context:
Blueprint Part 4.3 proposes FastAPI for the backend API. The foundation needs a web framework that supports async endpoints, automatic OpenAPI/Swagger documentation, and Pydantic-based request/response validation.

Problem:
Choose a Python web framework for the OSHI API layer.

Options:
1. FastAPI — modern, async-native, automatic OpenAPI docs, Pydantic v2 integration, strong ecosystem.
2. Django — batteries-included but heavier, ORM-coupled, less aligned with the modular monolith AI/agent focus.
3. Flask — lightweight but requires more boilerplate for async and validation.

Decision:
Use FastAPI 0.115.x.

Consequences:
- Automatic OpenAPI docs at `/docs` and `/openapi.json`.
- Pydantic v2 models used directly for request/response validation.
- Async route handlers support `httpx` for external API calls.
- `TestClient` available for integration testing without running a server.

Security implications:
- Rate limiting and authentication not yet implemented (planned for Sprint 1+).
- Input validation via Pydantic reduces injection risk.

Alternatives rejected:
- Django: overengineered for a modular API-first foundation.
- Flask: more manual work for validation and OpenAPI.

Date: 2026-11-14
