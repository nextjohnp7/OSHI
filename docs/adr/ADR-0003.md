ADR-0003: Use OpenAlex as the first scientific publication connector

Status: Accepted

Context:
Blueprint Part 6.1 lists candidate scientific data sources (OpenAlex, Crossref, Europe PMC, PubMed, Semantic Scholar, arXiv, DOAJ, Zenodo, NASA Earthdata, World Bank). The foundation needs at least one working connector to demonstrate publication search, normalization, and storage.

Problem:
Which scientific data source to integrate first for the ORI MVP.

Options:
1. OpenAlex — open scholarly index, no API key required for basic usage, REST JSON API, rich metadata (titles, authors, dates, abstracts via inverted index, locations/URLs, licenses).
2. Crossref — DOI-focused, requires polite pool email, good metadata but less full-text coverage.
3. Semantic Scholar — strong AI/CS coverage, API key needed for higher rate limits.
4. arXiv — preprint-focused, good for STEM but limited to one domain.

Decision:
Use OpenAlex (https://api.openalex.org/works) as the first connector.

Consequences:
- `packages/connectors/scientific/openalex.py` implements search + normalize.
- Basic usage works without an API key; `mailto` parameter joins the polite pool for higher rate limits.
- Abstract reconstructed from `abstract_inverted_index`.
- Authors extracted from `authorships`.
- Source URL from `primary_location.landing_page_url`.
- Rate limits and terms must be respected (https://docs.openalex.org/).

Security implications:
- Retrieved content treated as untrusted (Blueprint Part 8.2).
- No API key stored in code; `mailto` optional configuration.

Alternatives rejected:
- Crossref: strong DOI coverage but OpenAlex provides broader metadata in a single endpoint.
- Semantic Scholar: API key gating for higher limits complicates zero-config dev.
